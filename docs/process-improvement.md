The existing v2 audit records wall-clock milestones: 2h 08m 43s between initial approval and the JPA amendment, then 32m 55s to the first JPA implementation commit and 1h 59m 45s to final delivery. These include owner waits, design changes, checking and handoffs, not measured per-agent effort. It records nine ordinary full-E2E entries plus focused/negative runs. The v3 playbook's “about 1h20m” build claim is author-reported and unverified here. No v3 commands, services or tests were executed in this comparison.

## Recommended operating changes

1. Define a small outcome and changed-file scope before assignment. Use the existing clock to record start/deadline, a checkpoint at eight minutes if still working, and a safe stop by ten. Report completed/remaining work, actual commands/exits and resource/dirty state in the existing packet. No new timer infrastructure or automatic renewal of the same unfinished assignment.
2. Reuse accepted UX/architecture for routine changes within the approved baseline. Record the delta; involve those roles only for changed screens/contracts/invariants or material choices. A new feature still has a concrete design and pre-code validator plan reviewed by the owner.
3. Show one real vertical slice early after design approval. Check the actual request through UI, service and PostgreSQL before multiplying forms/scenarios. Reuse shared form actions, error helpers and layout patterns purposefully; verify the visual target during design rather than discovering it at acceptance.
4. Let independent validator/reviewer investigate stable code concurrently with exclusive scopes. Serialize writing to the feature packet and commands that share mutable outputs. Consolidate known findings into one correction batch, then rerun affected checks on the corrected revision.
5. Use about five readable acceptance groups with full underlying scenario coverage. Select changed-area checks; preserve earlier evidence for unchanged areas. Budget long commands explicitly as bounded assignments, mark unfinished execution pending, and never run historical full setup verification just to produce another notification.

Keep TDD, separate role sessions, Testcontainers, MSW isolation, real E2E and exact-money/date/ownership invariants. Two human checkpoints remain. Full original scenario completion still requires every original assertion; feature acceptance cannot complete deferred clauses. No v3 adoption, source migration, infrastructure refactor or finance scope choice is made here.
