## What changed in plain English

The browser reader now presents the same Markdown the agents write, with navigation to the current feature, questions, actual human decisions, role tasks, architecture, test plan, explanations and operating guidance. Search stays local. Source diagrams become readable pictures, while their original text remains available below them. Each page names its Markdown file; code references outside the reader are visibly labelled paths you can copy into your editor.

The requirements capture freezes the finance text used for later planning. It records each scenario's ID and original source line, the state of the sibling repository and checksums of every original file. This helps you distinguish a requirement change from an implementation defect later. It does not implement or approve a finance feature.

## Docs port correction

Platform's [browser-check defect](platform-implementation.md#review-correction-work-and-docs-port-defect) showed that the viewer's fixed config port took precedence over VitePress CLI `--port`. Earlier static builds and renderer tests did not establish runtime port override correctness; that browser run is failed evidence, not a pass.
